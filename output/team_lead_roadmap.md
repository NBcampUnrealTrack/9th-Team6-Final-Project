# IsekaiClass 팀장 개발 로드맵

기준: `IsekaiClass_기획서_최종_1.pdf`(18쪽, 작성일 2026-10-02). 기획서의 8인 분담과 2026-12-10 최종 발표를 기준으로 정리했다. 아래의 운영 방식·우선순위·검증 기준은 실행을 위한 권고이며, 기획서의 제안 항목을 팀 확정 사항으로 바꾸지는 않는다.

## 1. 팀장의 책임과 우선순위

팀장의 가장 중요한 결과물은 다른 7명이 연결할 수 있는 공용 구조와, 실제 플레이 가능한 통합 빌드다.

| 우선순위 | 직접 해야 할 일 | 결과물 |
| --- | --- | --- |
| 1 | 공용 상태·시간·저장 구조, 인터페이스와 소유권 합의 | WorldState, Time, SaveGame, 연동 계약 |
| 2 | 통합, 빌드, QA, 일정과 범위 조정 | 마일스톤별 실행 파일, 결함 목록, 결정 기록 |
| 3 | DT 스키마·ID·현지화 규칙, 밸런스 기준 | 데이터 사전, ID_Registry, 밸런스 시트, Validator |
| 4 | 사운드, NPC 외형 제작 | 사운드 목록과 에셋, VRoid 외형 |
| 5 | 발표 자료·영상·리허설 | 슬라이드, 시연 영상, 발표용 빌드 |

2번 플레이어 담당이 과부하되면 인벤토리·장비 작업을 지원하되, 맡을 기능을 명확히 잘라 인계한다. 공용 시스템과 통합 일정이 함께 밀리지 않도록 다른 담당의 준비 작업·QA 참여를 조정한다.

2026-10-03 상태 업데이트: 공용 WorldState·두 시계·수동 4/자동 1 저장·치트·ID/DT 계약과 CSV 검사·기존 플레이어 연결이 구현됐다. 저장 화면·삭제·종료·F6·상자·뒤로가기도 수정했다. Editor/Game 컴파일과 프로토 검증을 수행했으며 패키징 배포본과 실제 GAS/NPC/퀘스트 통합은 남아 있다. 현재 다음 작업은 [team_lead_next_steps.md](team_lead_next_steps.md)를 따른다. 아래 일정표와 체크리스트는 원래 전체 계획이며 완료 여부는 최신 검증 문서와 구분해서 읽는다.

## 3. 프로토타입: 10/2~10/8

### 10/2 D1: 다른 파트가 바로 호출할 약속을 공개한다

- [ ] 1~8번 담당에 실제 이름을 연결한다.
- [ ] 모두 저장소를 클론하고 같은 엔진·플러그인 환경에서 프로젝트를 여는지 확인한다.
- [ ] Git LFS 또는 Perforce, 에셋·레벨·DT 소유권, 병합 규칙을 정한다. 현재 `.gitattributes`에는 Unreal 에셋 등의 LFS 규칙이 있다. 팀원 PC의 설치·클론 정상 동작은 별도로 확인한다.
- [ ] 공용 함수 헤더와 최소 호출 예제를 공개한다. 구현이 늦으면 임시 응답으로 다른 담당의 작업을 진행시킨다.
- [ ] NPC·아이템·퀘스트·스킬 DT의 필수 컬럼과 ID 번호 대역을 정한다.
- [ ] 프로토 콘텐츠 수량, 통합 맵, 검증 시나리오를 고정한다.

공용 계약에서 먼저 정할 내용:

| 계약 | 합의할 내용 |
| --- | --- |
| GetSnapshot(CharacterId/NpcId) | UI가 읽을 필드, 액터가 없을 때 반환값 |
| WorldState 변경 함수 | 스탯·호감도·모드·파티·아이템 상태의 소유권과 변경 이벤트 |
| TryAddItem | 남은 수량 반환; 드롭·거부·보상 보류 정책은 호출 측 결정 |
| GameClock / PlayClock | 단위, 메뉴 정지, 수면 점프 범위 |
| OnTimeJumped(from, to) | NPC 재배치·SP·농사 등 구독 담당 |
| 저장 전 Flush / 로드 후 복원 | 각 파트가 제출할 구조체, 호출 순서, 중복 스폰 방지 |

### 10/5 D2: 시간과 테스트 도구를 만든다

- [ ] WorldState의 최소 상태 구조와 조회·변경 이벤트를 구현한다.
- [ ] GameClock(게임 분), PlayClock(플레이 초)을 구현한다.
- [ ] 메뉴·일시정지 중 두 시계가 멈추게 한다.
- [ ] 수면은 GameClock만 점프시키고 시간 변경 이벤트를 보낸다.
- [ ] 치트 명령: 시간 이동, 아이템 지급, 호감도 설정, 순간이동.
- [ ] 각 파트의 단독 테스트 맵 결과와 막힌 연결점을 확인한다.

치트는 일과·영입·엔딩 조건을 빠르게 재현하는 QA 도구다. 일반 플레이 밸런스 검증은 치트 없는 별도 진행으로 확인한다.

### 10/6 D3: 저장·로드와 실제 데이터를 연결한다

- [ ] 수동 4슬롯과 오토 1개를 위한 세이브 구조·슬롯 구분을 만든다.
- [ ] SaveVersion과 각 파트의 저장 데이터 구조를 정한다.
- [ ] 초기 생성·시간·아이템·스탯·호감도·파티·퀘스트 등 프로토 범위의 상태를 저장하고 복원한다.
- [ ] 저장 직전 살아 있는 액터의 전투 상태를 WorldState에 반영한다.
- [ ] 로드 후 UI·플레이어·NPC가 복원된 상태를 읽도록 연결한다.
- [ ] 전투·대화·이벤트 중 저장 금지를 연결한다.
- [ ] 가짜 데이터를 실제 DT 데이터로 교체하고 파트 간 호출을 확인한다.

NPC 현재 좌표를 그대로 저장하는 대신 시간표로 계산해 복원하고, 동료는 플레이어 주변에 복원하는 것이 기획서 기준이다. 저장 대상은 기능 확장과 동시에 추가해야 한다.

### 10/7 D4: 한 맵에서 통합한다

- [ ] 각 파트 기능을 프로토 맵에 모은다.
- [ ] 전투 보상·인벤토리·경험의 서·선물·영입·동료 전투·수면 연결을 확인한다.
- [ ] 이벤트가 두 번 처리되거나 UI와 실제 데이터가 어긋나는 문제를 잡는다.
- [ ] 마감 전 병합을 동결하고 진행 불가 버그를 우선 해결한다.

### 10/8 D5: 실행 파일로 검증한다

- [ ] 신규 기능 추가를 멈추고 버그만 고친다.
- [ ] 6번과 패키징 빌드를 만든다.
- [ ] 에디터 밖에서 생성부터 저장·로드까지 확인한다.
- [ ] 시연 영상을 녹화한다.
- [ ] 치트 없는 플레이에서 전투 감각·설명 없이 가능한 조작·루프 이해도를 기록한다.

기획서의 10/16 첫 패키징 일정과 별개로, 프로토 완료 기준에는 10/8 패키징 1회가 있다. 10/8을 프로토 빌드 검증, 10/16을 중간 발표 범위의 패키징 점검으로 운영한다.

### 프로토 전체 시나리오

캐릭터 생성 → 몬스터 처치 → 보상 획득 → 경험의 서 사용 → 상인에게 재료 구매 → 빵·검 제작 → 빵 섭취와 선물 → 호감도 100 → 영입 → 동료 동행·전투·수동 스킬 → 사냥 퀘스트 완료 → 수면 → 저장 → 종료·재실행 → 로드.

프로토 콘텐츠: 전사 1직업·스킬 1개, 몬스터 1종, 영입형 1명·상인 1명, 퀘스트 1개, 빵·검 레시피, 필수 UI, 최소 마을·사냥터·침대·앵커.

- [ ] 10/16 패키징, 10/21 중간 점검, 10/23 발표용 빌드 고정을 주관한다.

## 5. 콘텐츠 확장: 11/2~11월 중순

### 최종 목표

- 지역 4개(R01~R04), 맵세트 총 8개 통합.
- 직업 4개·플레이어 스킬 16개.
- 지역 보스 4명·최종 보스 1명, 총 5명.
- NPC 52명: 영입형 24, 상주형 12, 배경형 16.
- 메인·사이드 퀘스트, 엔딩 퀘스트, 일반·히든 엔딩.
- 지정 NPC 10명 호감도에 따른 엔딩 판정.
- 요리·제작 우선, 농사·낚시·벌목·채광·채집 확장.

### 팀장의 작업

- [ ] 11월 중순 기능 동결일을 확정하고 각 파트의 남은 작업을 역산한다.
- [ ] R01에서 검증한 데이터·모션·일과 템플릿으로 확장하게 한다.
- [ ] 지정 엔딩 NPC 10명과 힌트 방식을 먼저 확정한다.
- [ ] SaveVersion 마이그레이션과 ID 폐기 규칙을 적용한다.
- [ ] 기능이 늘 때마다 세이브 대상과 로드 복원 절차를 갱신한다.
- [ ] 지역별 비전투·전투 8곡 + 최종 보스 1곡, BGM 총 9곡과 효과음을 점검한다.
- [ ] 외형 제작 수량과 파생 방식을 확정한다. 부록 제안은 고유 외형 약 36개이며, 8번의 공용 임포트·모션 파이프라인과 연결한다.
- [ ] 매주 패키징 QA 빌드를 확인한다.
- [ ] 부록 A의 남은 규칙을 결정 기록에 반영한다.

늘릴 순서: 기존 루프 안정화 → 최종 보스·엔딩까지 진행 연결 → 핵심 직업·동료·지역 데이터 → 추가 콘텐츠 수량. 동결 시점에는 새 게임부터 엔딩까지 실제로 진행할 수 있어야 한다.

일정 부족 시 축소 후보로 콘텐츠 수량, NPC 외형 파생 정도, 생활 품목 수, 연출 복잡도를 검토한다. 4지역·52명 등 확정 목표 변경은 팀장이 범위 변경으로 명시하고 문서에 기록한다. 컨트롤러·추가 언어는 기획서상 후순위다.

## 6. QA·폴리싱: 11월 중순~12/7

### 팀장이 직접 승인할 통합 검증

| 시나리오 | 통과 조건 |
| --- | --- |
| 저장→종료→로드 | 시간·아이템·스탯·NPC·파티·퀘스트·엔딩 상태 보존 |
| 메뉴 열기→닫기 | 두 시계 정지·재개, 입력 모드 복귀 |
| 수면→월드 갱신 | GameClock만 점프; NPC 재배치·SP 회복, PlayClock 타이머 미진행 |
| 영입→해고→재영입→로드 | 상태 보존, 파티 제한 준수, 동일 NPC 액터 중복 없음 |
| 동료 쓰러짐→수면→부활 | 수면으로 부활하지 않고 지정 아이템·스킬로 복귀 |
| 인벤토리 가득 참 | 전투 보상 잔량 드롭, 구매·제작·퀘스트 보상은 정해진 거부·보류 정책 |
| 상점 할인·강화 | 거래로 아이템·골드 복제 없음; 할인 후 구매가와 판매가 규칙 준수 |
| 저장 불가 상태 | 저장 금지·오토세이브 보류·안전 상태 후 실행 |
| NPC 9명만 호감도 100 | 최종 보스 처치 시 일반 엔딩 |
| 지정 NPC 10명 모두 호감도 100 | 최종 보스 처치 시 히든 엔딩 |
| 엔딩→월드 복귀→로드 | 엔딩 종류와 클리어 플래그 유지, 계속 플레이 가능 |
| 지역 이동·워프·보스·동료 4명 | 기준 PC와 설정을 고정해 1080p 60FPS 목표·프레임 저하 확인 |

크래시·진행 불가·저장 손실을 먼저 해결한다. 조작, 전투 감각, UI 읽기, 가격과 성장 속도, 사운드, 모션, 성능을 그다음 다듬는다.

신규 기능은 동결한다. 수정 후에는 그 결함 재현 절차와 영향을 받는 핵심 루프를 다시 확인한다. 세이브 파일 오류 시 현재 플레이 상태와 기존 정상 파일을 손상하지 않아야 한다.

## 8. 매일·매주 운영

1. 오전 10분: 어제 결과, 오늘 결과, 다른 파트를 기다리는 항목 확인.

### 매주

1. 금요일 패키징 빌드를 플레이하고 다음 주 범위를 확정한다.

4. 각 담당은 자신의 데이터 입력과 기능 검증까지 책임진다. 팀장은 파트 사이 연결과 전체 플레이를 승인한다.
