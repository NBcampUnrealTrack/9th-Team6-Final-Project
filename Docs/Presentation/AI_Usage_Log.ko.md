# IsekaiClass 팀 AI 활용 기록 양식

발표 자료에는 **AI 활용** 항목을 반드시 넣는다. 발표에서 **어떤 작업에 AI를 써서 어떤 효과가 있었는지, 어떤 방식으로 요청했는지, 결과를 사람이 어떻게 검토하고 수정했는지** 설명할 수 있도록 기록한다. 기능 하나나 주요 의사결정 하나를 단위로 삼는다.

## 작업이 끝날 때 기록하는 방법

1. 아래 양식을 복사해 이름과 날짜가 들어간 별도 Markdown으로 저장한다. 팀에 공유할 사례는 예를 들어 `Docs/Presentation/2026-11-05_작성자_대화연출.ko.md`에 둔다.
2. 요청 전문 대신 문제, 범위, 제약, 검증 방법이 드러나는 문장만 남긴다. AI가 수행한 작업과 팀원이 판단하거나 확인한 내용을 구분한다.
3. 커밋 또는 PR과 재현 조건을 붙인다. 적용, 비교 실험, 되돌림 중 상태를 표시하고, 테스트 경고와 미측정 항목도 구분한다.
4. 발표에 쓸 사례는 아래 평가 기준에 연결한다. 전후 이미지나 영상은 같은 조건으로 비교하고, 공유할 수 있는 경로나 링크를 남긴다.

## 복사해서 쓰는 기록 양식

```markdown
# YYYY-MM-DD 작업 이름

- 작성자 ·
- 상태 · 적용 / 비교 실험 / 되돌림
- 근거 · 커밋 또는 PR / 빌드·검사 환경 / 테스트 이름 / 캡처나 영상

## AI를 쓴 작업과 효과

- 문제와 목표 ·
- AI가 도운 단계와 실제 반영한 결과 ·
- 확인한 효과 · 기능 변화, 재현 절차, 전후 수치나 캡처 등

## AI에 요청한 방식

- 처음 준 맥락과 제약 ·
- 추가 요청으로 좁히거나 바꾼 점 ·

## 사람의 검토와 수정

- 내가 확인한 환경과 기준 ·
- 발견한 문제와 수정하거나 제외한 내용 ·
- 수정 후 다시 확인한 결과와 남은 항목 ·

## 발표에 쓸 근거

- 평가 기준 · 아래 표에서 해당하는 항목
- 화면에 보여줄 자료 ·
- 자료가 뒷받침하는 한 문장 ·
```

## 평가 기준에 맞춰 남길 근거

| 평가 기준 | 기록할 근거 |
| --- | --- |
| 핵심 플레이 기능 완성도 | 플레이 흐름, 완료 조건, 처음부터 끝까지 성공한 재현 절차 |
| 안정성 및 최적화 | 테스트 통과·경고·실패, 재현한 오류, 같은 환경에서 측정한 FPS·프레임 시간·메모리 |
| 플레이 품질과 사용자 경험 | 같은 조건의 전후 캡처, 사용자가 겪은 불편, 피드백을 반영한 결과 |
| 기술 선택의 근거와 설명력 | 비교한 방법, 선택한 이유, 적용 범위와 비용 |
| 버전 관리 및 코드 최적화 | 변경 커밋·PR, 병합 또는 되돌림 이유, 재사용한 코드나 줄인 중복 |

## 기록을 정리할 때 AI에게 붙여 넣을 요청

> `Docs/Presentation/AI_Usage_Log.ko.md`를 읽고 이번 작업을 양식대로 정리해줘. 내가 요청한 범위와 제약, 네가 도운 부분, 내가 검토해 바꾼 부분을 구분해줘. 실제 커밋과 테스트 결과를 확인하고, 캡처나 재현 절차를 근거로 붙여줘. 비교만 한 시도와 되돌린 시도도 적용 상태와 구분해줘. 사람 검토나 성능 수치가 확인되지 않으면 확인이 필요한 항목으로 표시해줘.

## 발표 장표 구성

아래 순서를 발표 시간에 맞춰 합친다. 시연은 청중이 화면에서 확인할 수 있는 결과부터 보여주고, 코드와 에디터 설정은 그 결과를 설명할 때 꺼낸다.

| 장표 | 청중이 알아야 할 내용 | 준비할 자료 |
| --- | --- | --- |
| 게임 소개 | 플레이어가 무엇을 하고 무엇을 목표로 하는가 | 게임 화면 한 장, 팀이 합의한 한 문장 |
| 핵심 플레이 | 어떤 행동을 하고 결과를 어떻게 확인하는가 | 시연 시작 위치, 입력 순서, 완료 화면 |
| 개발 문제와 기술 선택 | 무엇이 불편했고 어떤 대안을 비교했는가 | 같은 조건의 전후 화면, 선택한 방법과 적용 범위 |
| AI 활용 | 어디에 썼고, 어떻게 요청했으며, 누가 무엇을 검토·수정했는가 | 요청 예시 한 문장, AI 결과, 사람의 수정, 게임에서 확인한 결과 |
| 안정성과 협업 | 어떤 조건으로 검사했고 무엇을 기록했는가 | 빌드 종류·커밋, 테스트 결과와 경고, 병합 또는 되돌림 사례 |
| 결과와 남은 범위 | 무엇을 시연했고 무엇을 더 확인해야 하는가 | 적용 범위, 비교 실험, 재현이 필요한 항목 |

AI 사례 한 장에는 **플레이어가 겪은 문제 → AI에게 준 요청 → 사람이 바꾼 결정 → 화면에서 확인한 결과**를 순서대로 배치한다. 예를 들어 `Morph Target`은 **얼굴 모양을 움직이는 모델의 기존 조절값**으로 먼저 설명한다.

## 시연과 검증 자료를 준비하는 방법

- 시연마다 **담당자, 빌드 또는 커밋, 시작 세이브, 맵, 입력 순서, 성공 화면, 대체 영상**을 한 줄로 남긴다. 에디터에서 실행한 검사는 에디터 검사로, 패키징한 게임에서 확인한 것은 패키지 검사로 표시한다.
- 캡처 이름에 기능과 조건을 넣고 공유 경로에서 열어본다. 밝기라면 같은 캐릭터·카메라·그래픽 품질에서 시간대와 실내외를 기록한다. UI라면 입력 장치와 어느 화면에서 전환했는지 남긴다.
- 검증 결과에는 **일반 통과, 경고 포함 통과, 실패, 미실행**을 구분한다. 성능 개선을 발표할 경우 같은 사양·해상도·장면에서 전후 프레임 시간이나 메모리를 기록한다.
- 팀원의 사례를 합칠 때는 해당 작성자에게 본인의 요청과 수정 판단을 확인받는다. 슬라이드에는 대표 결과를 넣고, 전체 테스트와 커밋은 질문을 받을 때 찾을 수 있게 남긴다.

## 작성 예시

**2026-11-05 첫 퀘스트 대화 연출** · 적용 · `93d7356d`

- **AI 활용과 효과** · 기존 VRoid 얼굴 모프를 대사별 표정 데이터에 연결했다. 첫 퀘스트 세 줄의 화자, 입 모양, 카메라 전환을 데이터로 지정할 수 있게 됐다.
- **요청 방식** · 처음에는 세 줄만 적용하고 GIF로 확인하도록 범위를 제한했다. 이후 플레이어가 화면에 잡히는 줄에도 표정과 입 모양을 넣도록 요청 범위를 보완했다.
- **검토와 수정** · 사용자 피드백을 반영해 두 번째 줄에서 플레이어가 말하도록 변경했다. 화자 전환, 대화 종료 초기화, 남녀 프리셋을 자동화로 확인했다. 대화 관련 6건 중 일반 통과 3건, 경고 포함 통과 3건이었다.
- **발표 근거** · 첫 세 줄 재현은 플레이 품질, 데이터 테이블과 기존 모프의 재사용은 기술 선택에 연결한다. [대사 설정과 재현 절차](../Characters/Dialogue_Expressions.ko.md)
