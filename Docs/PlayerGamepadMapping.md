# 게임패드 입력 — 최신 dev 통합

## 지원 범위

Xbox와 Nintendo 버튼 형식을 대상으로 합니다. PC의 Nintendo Switch Pro Controller는 Steam Input 등으로 표준 게임패드 입력이 전달되는 구성을 전제로 합니다. Nintendo 콘솔 빌드나 Joy-Con 개별 연결 지원을 의미하지 않습니다. 실제 기기 인식과 버튼 동작은 미확인입니다.

게임 설정의 패드 레이아웃에서 Nintendo를 선택하면 적용됩니다(`GamepadLayout=0`, Xbox는 `1`). 기본값은 기존 Xbox를 유지합니다. 아래 표는 표준 입력의 버튼 위치와 패드의 실제 버튼 위치가 일치하는 기준입니다. Steam Input에서 A/B·X/Y를 추가 교환하면 게임의 레이아웃 전환과 중복될 수 있으므로 실기 확인이 필요합니다.

## 기본 매핑 (최신 dev 배치)

| 기능 | Xbox | Nintendo |
|---|---|---|
| 이동 / 카메라 | 왼쪽 / 오른쪽 스틱 | 동일 |
| 점프 | A (아래) | A (오른쪽) |
| 상호작용 | X (왼쪽) | X (위) |
| 낚시 | Y (위) | Y (왼쪽) |
| 메뉴 / 취소 | B 또는 Menu | B (아래) 또는 + |
| 비전투 달리기 | LT 유지 | ZL 유지 |
| 전투 닷지 | LT를 눌렀다가 놓기 | ZL를 눌렀다가 놓기 |
| 일반 공격 | RT | ZR |
| 타깃 전환 | LB | L |
| 무기 전환 | RB | R |
| 타깃 해제 | 오른쪽 스틱 클릭 | 오른쪽 스틱 클릭 |
| 지도 | View | − |
| 퀵슬롯 1~4 | 방향키 위·오른쪽·아래·왼쪽 | 동일 |
| 플레이어 스킬 | LT + X | ZL + X |
| 동료 스킬 1~3 | LT + Y/B/A | ZL + Y/B/A |

LT/ZL 조합키를 사용하면 해당 버튼 해제에서는 닷지를 실행하지 않습니다. 두 형식 모두 대상 선택 중 A 확인·B 취소이며, 기존 dev의 메뉴 입력 처리와 Nintendo 위치 변환을 사용합니다.

## 에셋과 코드 역할

- `Content/IsekaiClass/Input/Contexts/IMC_Gamepad`: 기본 패드 버튼, 기존 Input Action, 스틱 반경 데드존(0.2)을 저장합니다.
- `GamepadMappingContext`: 컨트롤러에서 참조하는 패드 전용 컨텍스트입니다. 키보드 설정 복사본에 들어 있는 패드 매핑은 제외하여 중복을 막습니다.
- 스틱은 Enhanced Input의 기존 Move/Look 액션을 실행합니다. 카메라의 초당 90도 기준 회전·프레임 시간·감도는 최신 dev의 Look 처리에 유지합니다. IMC에 시간 배율을 다시 넣지 않습니다.
- 버튼은 dev의 UI 선처리/조합키 라우터를 유지합니다. 라우터가 IMC의 키→Input Action과 CommandActions의 Action→Command 연결을 읽어 기존 행동 함수를 호출합니다. 일반 버튼의 고정 키 배치는 제거했습니다. LT 조합 및 대상 선택은 코드의 상황별 처리입니다. dev에 별도 ClearTarget Input Action이 없어 오른쪽 스틱 클릭 타깃 해제도 기존 코드 처리를 유지합니다.
- UI 확인/취소와 조합키의 얼굴 버튼 의미는 dev 설정을 따르므로 기본 버튼 에셋을 변경할 때 함께 고려해야 합니다.
- `Tools/Input/setup_gamepad_input.py`는 초기 에셋 생성용입니다. 재실행하면 에셋에서 수동 편집한 매핑을 덮어씁니다.
