# 저장 완성 이후 팀장 다음 작업

기준일: 2026-10-03. 기획서의 역할 분담과 마감을 현재 구현 결과에 맞춰 다시 정리했다. 사용자가 저장 정상 동작을 확인했고, 불러오기 뒤로가기 수정도 완료했다. 아래 진행 순서와 내부 제출 시점은 운영 권고이며, 기획서의 제안 사항을 확정하지 않는다.

## 1. 현재 어디까지 왔나

| 상태 | 항목 | 다음에 할 일 |
| --- | --- | --- |

컴파일된 Game exe는 배포 가능한 패키징 완료와 다르다. 이전 두 맵 게임 실행 검증은 UnrealEditor의 -game 실행이며, 별도 PC에서 설치 엔진 없이 실행되는 배포본 검증이 남아 있다.

현재 저장소에서 확인한 범위와 팀원 개인 브랜치/PC에서 만든 기능의 진행률은 별개다. 완료됐다는 보고는 통합본에서 직접 확인한 뒤 표시한다.

## 2. 지금 가장 먼저 할 다섯 가지

1. **공용 코드 인계.** 팀 저장소에 검토·공유 가능한 기준 버전을 정하고 팀원 PC에서 같은 엔진/플러그인으로 열리는지 확인한다. 실제 공유·커밋·푸시는 별도 실행 작업이다.
2. **담당 이름과 마감 연결.** 2~8번 영역에 실제 담당자를 붙인다. 작업 보드에 작업·책임자·마감·선행 작업·완료 기준·실행 결과 링크를 적는다.
3. **프로토 범위 고정.** 전사 1직업/1스킬, 몬스터 1종, 영입형 1명/상인 1명, 빵/검 제작, 사냥 퀘스트 1개, 최소 마을/사냥터/침대/작업대.
4. **단독 실행 결과 받기.** 각 담당에게 테스트 맵·작동 영상·연동할 함수·현재 막힌 항목을 받는다. 팀원 기능 구현 전체를 팀장이 대신 맡는 것으로 해석하지 않는다.
5. **6번과 통합 맵 지정.** L_TestMap 등을 후보로 검토하되 최종 맵은 팀장이 6번과 확정한다. 테스트 맵 작업을 계속하면서 통합 맵 소유자는 한 명으로 둔다.

공유할 기존 문서:

- [SystemContracts.md](../Docs/SystemContracts.md): 원본 소유권, 조회/변경, 저장, 시간, 입력 계약.
- [DT_Schema.md](../Docs/DT_Schema.md): ID/번호 대역, DT, String Table, 기존 데모 예외.
- [PrototypeAcceptance.md](../Docs/PrototypeAcceptance.md): 지금 검증된 기능과 실제 확인 순서.

## 4. 팀장이 직접 이어서 개발할 것

### 우선 1: 실제 파트와 저장·시간 연결

- 3번: SetCombatState와 실제 전투 시작/종료를 연결한다. 살아 있는 GAS 값이 Snapshot/Flush/복원에 반영되는지 확인한다.
- 5번: 대화·이벤트 시작/종료에서 저장 안전 플래그를 해제까지 정확히 전달한다.
- 2·4번: 실제 수면 시간 계산/회복 후 JumpGameMinutes 호출, NPC OnTimeJumped 구독과 재배치 순서를 맞춘다.
- 5·6번: 퀘스트 수락/완료·워프/지역 이동·보스 처치에서 RequestAutoSave를 호출한다.
- 모든 파트: 전투·대화·이벤트 중 자동 요청은 보류되고 종료 후 처리되는지 확인한다.

이미 있는 API를 먼저 사용한다. 호출 자체가 준비돼 있다는 사실은 실제 이벤트 연결 완료를 뜻하지 않는다.

### 우선 2: 정식 데이터와 검사

- ID_Registry 예약 대역에서 팀원 데이터의 ID를 확정한다.
- 데모 Food/Wood/Sword 등을 정식 데이터로 옮길 때 기존 저장 호환을 함께 설계한다.
- 팀원 DT의 Row Name/ID 일치, 참조 ID·에셋·스킬·소켓 누락을 검사한다.
- 현재 CSV 검사에 더해 Unreal 에디터에서 실제 DataTable/에셋을 검사하는 Validator를 준비한다.
- 한국어 표시 문자열을 String Table로 옮기는 일은 7번과 각 콘텐츠 담당이 수행한다.

파일별 신규 생성/수정 계획은 후속 구현안에서 제시한 뒤 승인받는다. 새 게임 기능을 이 문서 작성으로 자동 승인된 것으로 간주하지 않는다.

### 우선 3: 밸런스 결정

[BalancePrototype.csv](../Data/BalancePrototype.csv)의 Pending 항목을 담당과 결정한다.

- 수면 최소 시간과 SP 회복 기준: 2번.
- 피해·치유·탈진·디버프·전투 종료 판정: 3번.
- 선물 호감도·상점 가격·할인/판매 정책: 4·5번.
- 팀장은 치트 없는 실제 루프의 길이·보상 체감·진행 속도를 보고 확정한다.

결정 기록에는 값·이유·담당·적용 코드/DT·확인 방법을 남긴다. 현재 CSV는 런타임에 자동 반영되는 설정 파일이 아니다.

본문의 10/9 회고와 부록의 날짜 이동 권고가 함께 있으므로 회고 날짜는 팀장이 확정한다. 표의 세부 운영은 권고다.

**완주 시나리오**

캐릭터 생성 → 전투/처치 → 보상 → 경험의 서 → 상점 구매 → 빵·검 제작 → 빵 섭취/선물 → 호감도 100 → 영입 → 동료 동행/스킬 → 사냥 퀘스트 → 수면 → 저장 → 게임 종료 → 재실행/복원.

통합 순서는 전투/보상 → 성장/제작 → 선물/영입 → 일과/수면 → 전체 저장 복원으로 작게 나눈다. 첫 연결이 막히면 각 담당이 임시 응답과 교체 기한을 정한다.
