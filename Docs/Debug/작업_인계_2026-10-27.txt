1. 사용자가 원하는 다음 작업 순서

현재 Leader의 작업을 먼저 커밋한다.
다른 팀원들이 PR을 통해 dev에 작업을 합친 뒤, 최신 dev를 Leader에 반영한다.
이때 충돌과 통합 후 문제를 수정하고 검증하여 Leader를 Push하고 dev 대상 PR로 보낸다.
이 문서는 그 시점에 현재 구현을 놓치지 않고 바로 이어서 작업하기 위한 기록이다.
이번 인계 기록 작업에서는 커밋·Fetch·병합·Push·PR 생성을 실행하지 않았다.

3. 새 시나리오의 적용 제한

사용자는 시나리오 때문에 게임 시스템이나 DT를 바꾸지 말고 텍스트만 작성하라고 요청했다.
Docs/Scenario/R01_새_시나리오.txt는 의뢰 55개의 새 시나리오 원고이며 게임에 적용하지 않았다.
첨부 원고와 실제 시스템·아이템 ID를 참고하여 작성했고, 미등록 장소·소품은 제안으로만 남겼다.
다음 통합 작업에서 이 원고를 근거로 퀘스트나 시스템을 자동 구현하지 않는다.

5. dev 병합 후 바로 확인할 부분

먼저 작업 브랜치, 커밋 여부, 로컬 변경, 원격 dev의 최신 상태를 확인한다.
사용자가 팀 변경 반영을 요청하면 Fetch 후 현재 Leader에 최신 origin/dev를 병합한다.
팀이 공유하는 브랜치의 기존 커밋 기록을 임의로 다시 쓰지 않는다.

변경이 겹치기 쉬운 부분:
- L_TestMap.umap의 제작대·주방·뽑기 기계 배치와 다른 팀원의 맵 변경.
- DA_IC_DefinitionCatalog, ID 레지스트리, 새 DT 연결.
- DT_IC_Item, DT_IC_Recipe, 생활 DT, ST_IC_Definitions/ST_IC_UI와 CSV 원본의 일치.
- PlayerController의 입력·UI·저장 흐름과 PlayerCharacter의 무기 전환.
- 닭 BP 부모 클래스, 가방 초과 드롭과 보상 경로.
- 아이템 삭제에 따른 퀘스트·선물·상점 참조 및 저장 호환 코드.

에셋 충돌은 소스와 실제 연결을 확인하여 해결한다. 한쪽 에셋을 일괄 채택하면
다른 팀원의 배치나 이 작업의 DT/BP 연결이 빠질 수 있으므로 최종 내용을 확인한다.
CSV만 바꾼 뒤 실제 DT 에셋이 갱신되지 않은 상태로 완료 처리하지 않는다.
Tools/Life/setup_gacha_and_drops.py, configure_life_data.py 등은 초기 데이터 설정 도구다.
기존 DT 편집 내용을 확인하지 않고 통째로 재실행하여 팀원의 밸런스 수정을 덮어쓰지 않는다.

통합 후에는 Editor 빌드와 영향받은 자동 검사, 테스트맵 PIE를 확인한다.
검증 도구:
- Tools/Characters/review_weapon_switch.py
- Tools/Combat/review_sword_combo_damage.py
- Tools/Life/review_crafting_stations.py
- Tools/Life/review_life_calendar.py
- Tools/Life/review_gacha.py

빌드: Tools/BuildProject.ps1
실제 에디터가 프로젝트 DLL을 사용 중인지 확인하고 빌드한다.
PIE 검토 도구는 분리된 테스트 저장 공간을 사용하므로 기존 사용자 세이브를 검증용으로 덮어쓰지 않는다.
수정과 검증을 끝내면 최종 변경 내용 기준으로 커밋 메시지를 정리하여 Push/PR을 진행한다.
이전 커밋이 이미 dev에 들어갔는지도 확인하여 중복 변경을 만들지 않는다.
