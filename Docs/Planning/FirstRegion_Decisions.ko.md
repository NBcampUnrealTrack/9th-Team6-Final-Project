# 첫 지역 실제 플레이 제작을 위한 결정 목록

작성일: 2026-10-20. 사용자 기획서와 현재 프로젝트 파일을 확인해 정리한 작업용 문서다.

표시 기준: **확정**은 기획서 또는 이번 요청에 있는 내용, **결정 필요**는 사용자의 선택이 필요한 내용, **제안**은 아직 승인되지 않은 초안이다. 비어 있는 답변은 확정으로 취급하지 않는다. 구현 방식과 내부 자료형은 개발 과정에서 정하며, 사용자는 플레이 결과와 콘텐츠를 결정하면 된다.

## 1. 이미 정해진 내용

- 타이틀은 `L_Title`, 기능을 통합할 실제 플레이 테스트 맵은 `L_TestMap`, 최종 월드는 `L_OpenWorld`로 사용하려는 방향이다.
- 메인 메뉴에는 **이세계클래스**라는 제목 텍스트와 **시작하기 / 이어하기 / 설정 / 끝내기** 네 버튼을 표시한다.
- 싱글 플레이, 3인칭 액션, 한국어 우선이다. 캐릭터 직업을 고정하지 않고 검 / 활 / 마법스태프 / 치유완드 4종 무기를 교체한다.
- 캐릭터 생성 질문과 선택지 문구는 기획서에 있다. 질문 4의 선택으로 NPC 기술 1개와 그 계열 초보 무기 1개를 받는다.
- 기본 조작키, GameClock / PlayClock, 호감도 보상 단계, 인벤토리 규칙, 저장 슬롯 규칙은 기획서 기준이다.
- 성장 스탯은 STR / DEX / CON / INT / LUK 다섯 가지다. 캐릭터 레벨, 직업 레벨, 생활 숙련도는 사용하지 않는다.
- 동료는 최대 3명, 펫은 전투 없이 추종한다. 퀘스트 기본 목표는 처치 / 방문 / 대화 / 아이템 소유 네 종류다.
- 중간 발표 기획 수량은 **한 지역, NPC 10명, 일반 몬스터 10종, 보스 1명, 제작 레시피 20개, 퀘스트 20개, 낮밤 / 일과 / 저장·불러오기**다. 변경 답변이 없다면 이 수량을 기준으로 계획한다.

## 2. 테스트 맵을 사용하는 방법

`L_Title → 시작하기·이어하기 처리 → L_TestMap → 최종에 L_OpenWorld` 흐름은 적절하다. `L_TestMap`을 첫 지역의 실제 플레이를 완성하는 공간으로 사용한다.

기능은 공용 C++ / BP / 데이터에 두고, 맵에는 시작 지점, NPC 일정 지점, 스포너, 방문 영역, 집과 시설 등을 배치한다. NPC ID / 퀘스트 ID / 아이템 ID는 맵 이름과 분리하고, 최종 맵에서는 같은 콘텐츠에 새 배치 위치를 연결한다. 기능 로직을 테스트 맵의 Level Blueprint와 특정 액터 직접 참조에 집중시키지 않는 방식을 제안한다.

현재 확인한 사항:

- `Config/DefaultEngine.ini`의 GameDefaultMap과 EditorStartupMap은 이미 `L_TestMap`이다. `L_Title`에서 시작하는 흐름을 만들 때 게임 실행 기본 맵과 메뉴의 목적지 설정을 따로 확인해야 한다.
- 메인 메뉴 C++에는 실제 플레이 목적지인 `StartMap` 속성이 있다. WBP에 저장된 실제 속성값과 레벨별 GameMode 설정은 에디터에서 추가 확인해야 한다.
- 관련 공용 C++와 DT 원본 CSV가 있다. 파일 존재만 확인했으며, 전체 기능의 실제 플레이 완성을 검증한 상태는 아니다.
- 일부 기존 코드와 예시 데이터는 새 기획과 다르다. 예를 들어 우클릭 방어, Shift 짧게 회피 / 길게 달리기, 여러 직업 스킬 슬롯, 시작 무기 4종 지급, 추가 스탯과 장비 예시가 남아 있다. 사용자가 기획을 바꾸지 않는 한 기획서에 맞추는 작업으로 처리한다.
- 이 문서 작성 과정에서 코드, 설정, BP, 맵, DT를 수정하지 않았다.

최종 맵 이전 시에는 배치 위치, 고유 ID 중복, NavMesh, NPC 이동 경로, World Partition 언로드·재로드, 지도 좌표, 저장 위치 호환성을 확인한다. 기존 테스트 저장을 최종에서 유지할지 여부만 사용자가 결정하면 된다. 맵 파일 하나를 바꾸는 것만으로 이전 검증이 끝나는 것은 아니다.

건물·관심 지점의 재사용 가능한 배치는 Level Instance도 후보가 된다. 실제 채택은 맵 구조를 확인한 후 정한다. [Epic: 레벨 인스턴싱](https://dev.epicgames.com/documentation/ko-kr/unreal-engine/level-instancing-in-unreal-engine), [Epic: World Partition](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine).

## 4. 지역과 플레이 흐름

- [ ] W01. 지역 이름 / 분위기 / 사용하는 배경 에셋을 고른다. 제안: R01 시골 마을 + 주변 사냥터 + 중간 보스 장소.
- [ ] W02. 플레이어 집, 마을 중심, 상점, 제작대, 주방, 농장, 채집·채광 장소, 낚시터, 일반 사냥터, 보스 장소의 대략적인 배치를 정한다. 좌표 대신 간단한 배치 그림이나 설명으로 답해도 된다.
- [ ] W03. 새 게임 시작 위치, 첫 등장 시각, 시작 골드와 기본 물품을 정한다. 무기 지급은 기획서의 첫 기술 계열 무기 1개를 따른다.
- [ ] W04. 집 내부를 같은 월드에 둘지, 별도 내부 공간으로 이동할지 정한다. NPC 집도 같은 규칙을 적용할지 정한다.
- [ ] W05. 중간 보스 접근을 자유롭게 할지, 퀘스트·상호작용 후 입장할지 정한다. 전투 중 이탈과 재도전 위치도 정한다.
- [ ] W06. 보스 처치 후 보상 / 지역 지도 공개 / NPC 대사 변화 / 다음 목표 안내를 정한다. 지도 공개 규칙은 기존 기획을 따른다.
- [ ] W07. 한 번의 실제 플레이 목표 시간과 발표에서 보여 줄 시연 동선을 정한다.
- [ ] W08. 테스트 저장을 최종 맵에서도 이어 쓸지 정한다. 유지한다면 옛 좌표 대신 대응 시작·워프 지점으로 보내도 되는지 정한다.

- [ ] UI01. 전체 UI의 참고 이미지 또는 색감·폰트·버튼 스타일을 정한다. 임시 디자인을 허용할 항목도 표시한다.

## 6. 입력·이동·카메라

기본 키는 아래 기획서 값을 먼저 적용한다. 기존 코드·에셋과의 차이는 구현에서 맞춘다.

| 행동 | 기획서 키 |
| --- | --- |
| 이동 / 시점 | WASD / 마우스 |
| 공격 / 무기 교체 | 좌클릭 / 우클릭 |
| 회피 대시 / 점프 / 적 전환 | Shift / Space / TAB |
| 현재 무기 스킬 / 동료 스킬 | Q / E·R·T |
| 퀵슬롯 / 상호작용 / 낚시 | 1·2·3·4 / F / H |
| 파티 / 인벤토리 / 퀘스트 / 도감 / 설정 | Y / U / I / O / P |
| 취소 / 일시정지 | ESC |

- [ ] IN01. WASD 기본 이동이 걷기인지 달리기인지, 걷기 전환 키가 필요한지 정한다. Shift는 기획상 회피이며 별도 전력질주는 추가 요구가 있을 때 정한다.
- [ ] IN02. 우클릭 무기 변경은 보유 슬롯 순환 / 선택창 / 길게 누르는 원형 메뉴 중 어떤 느낌인지 정한다. 슬롯 순서와 비어 있는 슬롯을 건너뛸지도 정한다.
- [ ] IN03. 비전투에서는 이동 방향으로 회전할지, 항상 카메라 방향을 볼지 정한다. 전투 중 적을 바라보며 좌우 이동할지도 정한다.
- [ ] IN04. 카메라 거리·높이·좌우 치우침·줌·감도·상하 반전, 타깃 선택 시 카메라가 적을 따라가는지를 정한다. 수치는 첫 플레이 후 조정해도 된다.
- [ ] IN05. 회피는 짧은 스텝 / 미끄러지는 대시 / 구르기 중 무엇인지 정한다. 입력 방향이 없을 때의 방향, 공중 회피 여부, 무적 구간도 정한다. 쿨타임 3초와 SP 미소모는 기획서 값이다.
- [ ] IN06. 일반 공격·스킬 중 이동, 방향 전환, 회피 취소, 피격 중단을 허용할 범위를 정한다.
- [ ] IN07. 공격은 한 번 클릭마다 1회인지 / 누르고 있으면 반복인지, 검 연타 콤보는 몇 타인지 정한다.
- [ ] IN08. 대상 지정 모드의 자기 자신·동료 선택 표시와 확정 피드백을 정한다. E/R/T 재입력 자기 지정 규칙은 기획서 기준이다.
- [ ] IN09. 중간까지 게임패드 입력·UI 포커스·키 재지정을 모두 구현할지 정한다. 키보드·마우스는 기본 범위다.
- [ ] IN10. 대화 중 시간 정지 여부, 이동·카메라 조작 가능 여부, 대화 종료 입력을 정한다.

## 7. 플레이어·무기·애니메이션

- [ ] CH01. 남 / 여 플레이어 모델과 중간 발표에 사용할 외형을 고른다. 현재 샘플에 `SK_Player_M`, `SK_Player_F`가 존재한다. 기본 외형만 사용할지 추가 커스터마이징을 제공할지 정한다.
- [ ] CH02. 질문 4의 각 음악 선택지를 시작 마을의 어떤 NPC에 연결할지 정한다. 각 NPC의 호감도 100 기술이 시작 기술이고, 해당 계열 무기 1개를 지급한다.
- [ ] CH03. 질문 3의 선택으로 주는 정보·선물 레시피의 실제 내용을 정한다. 질문 5는 보상 없음으로 유지한다.
- [ ] CH04. 무기를 손에 계속 들고 있을지, 비전투 때 수납할지, 교체 시 꺼내기·넣기 연출을 넣을지 정한다.

애니메이션은 다음 용도별로 선택한다. 모든 파일을 하나씩 고르는 것이 아니라 **실제로 쓰는 상태와 동작**에만 배정한다.

```text
목표 2: ... / 앞 목표 다음인지, 동시인지
완료 조건 / 보고 NPC / 제출할 아이템:
보상: 골드 / 엘릭서 / 아이템 / 호감도
진행 중 대사 / 완료 대사:
```

호위 같은 새 목표 유형은 기본 범위에 추가하지 않는다. 채집·제작 과제는 해당 아이템 소유와 제출로 표현할 수 있다. 이미 가진 물건 인정, 현재 수량 재검사, 보상 중복 방지는 기획 규칙대로 구현한다.

## 14. 저장·시연 완료 기준

수동 4슬롯 + 자동 1슬롯, 저장 제한, 자동 저장 계기, 사망 후 슬롯 선택은 기획서에 정해져 있다.

- [ ] QA01. ‘이어하기’가 최신 저장 직행인지 슬롯 목록인지 결정한다. UI 항목과 동일 결정으로 처리한다.
- [ ] QA02. 초저HP 자동 저장 보류 기준 같은 아직 비어 있는 수치는 직접 지정 / 초안 위임을 선택한다.
- [ ] QA03. 발표 PC·입력 장치·목표 해상도·시연 시간을 정한다. 기존 성능 목표는 PC 1080p 60FPS다.
- [ ] QA04. 아래 시연 흐름에 넣을 실제 NPC·퀘스트·아이템·보스 이름을 정한다.

완성 확인 흐름 제안:

1. 실행하면 L_Title과 확정한 네 버튼이 나온다.
2. 새 게임 → 캐릭터 생성 → L_TestMap 첫 지역의 집에서 시작한다.
3. 이동·카메라·점프·회피, 상호작용·메뉴 입력을 확인한다.
4. 첫 NPC 대화 → 퀘스트 수락 → 채집·아이템 획득 → 제작·사용을 진행한다.
5. 선물·호감도 보상 → 동료 영입 → 전투·동료 스킬을 확인한다.
6. 4무기와 개별 스킬 쿨타임을 검증하고, 중간 보스까지 진행한다.
7. 낮밤·NPC 이동·퇴근·수면과 수면 후 일정·자원 규칙을 확인한다.
8. 저장 후 종료·재실행 → 인벤토리·퀘스트·파티·시간·보스 상태를 복원한다.
9. 중간 발표에서 완료하기로 한 펫·낚시·농사 등 추가 기능을 실제 플레이로 확인한다.
10. 에디터 밖 패키징 빌드에서도 같은 흐름과 목표 성능을 확인한다.

저장은 첫 연결 흐름부터 검증한다. 마지막 단계까지 미뤄 두는 작업이 아니다. 대표 콘텐츠로 먼저 한 바퀴를 연결한 뒤 계획된 10 NPC / 10종 / 20 퀘스트 / 20 레시피로 확장하는 순서이며, 최종 수량을 자동으로 줄인다는 의미가 아니다.

## 16. 첫 답변용 양식

```text
1. 첫 지역·분위기:
2. 이번 보스의 역할·외형:
3. 중간 발표 수량: 원안 유지 / 변경 내용
4. 첫 통합에서 볼 플레이어 외형·무기:
5. 메인 메뉴: 배경 / 제목·버튼 위치 / 색감·폰트 / BGM
6. 이어하기: 최신 저장 직행 / 슬롯 목록
7. 이동·카메라·회피 느낌:
8. 첫 NPC·첫 퀘스트·보스로 이어지는 이야기:
9. 중간까지 반드시 완성할 기능:
10. 수치와 애니메이션 후보 초안: 직접 지정할 부분 / 제안받을 부분
```

이후 해당 단계에서 NPC 한 명, 기술 한 개, 퀘스트 한 개, 아이템·레시피 한 개의 양식을 채우고 검토한 뒤 같은 형식으로 확장한다.
